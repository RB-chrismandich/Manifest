# Token Benchmark: Before/After Manifest Measurement System

**Date**: 2026-06-12
**Status**: Draft
**Goal**: Measure input/output token costs and quality deltas for Claude, Gemini CLI, and Antigravity CLI before and after manifest config deployment, using industry-standard benchmark prompts.

---

## Problem

Applying the Manifest (via `bootstrap.sh`) deploys CLAUDE.md, GEMINI.md, and Antigravity configs to `~/.claude/`, `~/.gemini/`, and `~/.antigravity/`. These configs are loaded as system context on every CLI invocation, adding input token overhead. There is currently no way to answer:

- How many extra input tokens does the manifest add per request?
- Does manifest deployment change output verbosity or quality?
- Do these numbers change as the manifest configs evolve?

---

## Scope

Three providers: `claude` (Claude CLI / Anthropic API), `gemini` (Gemini CLI / Google API), `antigravity` (Antigravity CLI).

Two measurement axes:
1. **Token cost** — exact input/output token counts via API response objects
2. **Quality delta** — answer correctness against known gold answers, via CLI binary invocations

Two conditions per run: **before** (no manifest configs present) and **after** (manifest configs deployed).

## Architecture

```
tests/
└── token_benchmark/
    ├── harness.py          # Core runner: isolated HOME setup, API+CLI dispatch
    ├── benchmarks.py       # Prompt fixtures (MMLU/HumanEval/HellaSwag/TruthfulQA)
    ├── scorer.py           # Quality scoring (exact match, pass@1 for code)
    ├── reporter.py         # JSON → Markdown report generator
    ├── results/            # Timestamped JSONL result files (committed; contain only token counts + scores, no prompts or API keys)
    └── fixtures/
        └── manifest/       # Committed snapshot of deployed manifest configs
            ├── .claude/
            │   ├── CLAUDE.md           # Primary context overhead source
            │   └── settings.json       # Hooks + tool permissions (affects CLI behavior)
            ├── .gemini/
            │   └── GEMINI.md
            └── .antigravity/
                └── (provider-specific config files, discovered at --sync-fixtures time)

docs/
└── TOKEN_BENCHMARK.md      # Living report — regenerated by skill, committed

.skillshare/skills/
└── token-benchmark/
    └── SKILL.md            # /token-benchmark skill
```

### Data Flow

```
/token-benchmark
       │
       ▼
harness.py
  ├── Creates two tmpdir HOME dirs: empty_home (before), manifest_home (after)
  ├── Copies fixtures/manifest/ → manifest_home
  ├── For each prompt in benchmarks.py (20 prompts × 2 conditions × 3 providers):
  │     ├── API path  → exact token counts from response.usage
  │     └── CLI path  → response text with HOME overridden per subprocess
  ├── scorer.py evaluates output text vs. gold answers
  └── reporter.py diffs before/after → writes TOKEN_BENCHMARK.md
```

Each run appends a timestamped JSON file to `tests/token_benchmark/results/`. The skill regenerates `TOKEN_BENCHMARK.md` from all result files in that directory, so historical runs are preserved and comparable.

## Benchmark Suite

20 prompts across 4 categories, each with a known gold answer:

| Category    | Count | Format                        | Scoring               |
|-------------|-------|-------------------------------|-----------------------|
| MMLU        | 6     | Multiple choice (A/B/C/D)     | Exact match on letter |
| HumanEval   | 6     | Python function completion    | `pass@1` (subprocess sandbox: `python -c` with 5s timeout, no network) |
| HellaSwag   | 4     | Sentence completion (0/1/2/3) | Exact match on index  |
| TruthfulQA  | 4     | True/False + explanation      | Exact match on T/F    |

**Prompt selection**: Representative questions from published datasets, spanning high-school science, mathematics, common sense reasoning, factuality, and code generation. Prompts are fixed in `benchmarks.py` — they never change between runs, ensuring comparability.

**Token measurement per prompt (API path):**

```
before:
  input_tokens  = prompt_tokens                          (no system context)
  output_tokens = response_tokens

after:
  input_tokens  = manifest_tokens + prompt_tokens        (manifest injected as system)
  output_tokens = response_tokens

overhead_per_call = after.input_tokens − before.input_tokens
```

## Harness Implementation

### Isolated HOME Directories

Two temporary directories are created at the start of each run:

```python
empty_home    = tempfile.mkdtemp()   # no config files — "before" state
manifest_home = tempfile.mkdtemp()   # fixtures/manifest/ copied here — "after" state
```

Both are deleted at run end. The `manifest_home` is populated from the committed `fixtures/manifest/` snapshot, not from the live `~/.claude/` — this makes the "after" state reproducible without requiring a live environment.

### API Path (Exact Token Counts)

**Claude** — Anthropic SDK, captures `response.usage`:
```python
response = await client.messages.create(
    model=model,
    system=system_prompt,  # "" for before, CLAUDE.md content for after
    messages=[{"role": "user", "content": prompt}],
    max_tokens=1024,
)
tokens = {"input": response.usage.input_tokens, "output": response.usage.output_tokens}
```

**Gemini** — Google Generative AI SDK, captures `usage_metadata`:
```python
response = model.generate_content([system_prompt, prompt])
tokens = {
    "input": response.usage_metadata.prompt_token_count,
    "output": response.usage_metadata.candidates_token_count,
}
```

**Antigravity** — no SDK available; token counts from the API path are not measurable. The column shows `—` in the report. If Antigravity's CLI emits token counts in `--verbose` output in the future, `harness.py` will parse them via a configurable regex.

### CLI Path (Behavioral Delta)

```python
env = os.environ.copy()
env["HOME"] = str(empty_home if condition == "before" else manifest_home)

result = subprocess.run(
    cli_cmd,               # ["claude", "--print", prompt], ["gemini", "-p", prompt], etc.
    env=env,
    capture_output=True,
    text=True,
    timeout=60,
)
```

CLI binary names and flags are configured per provider in `benchmarks.py`, not hardcoded, so adding a new provider requires only a config entry.

### Result Schema

Each result record (written to `results/YYYY-MM-DDTHH-MM-SS.jsonl`):

```json
{
  "run_id": "2026-06-12T14:30:00",
  "provider": "claude",
  "model": "claude-sonnet-4-6",
  "condition": "after",
  "category": "mmlu",
  "prompt_id": "mmlu_003",
  "input_tokens": 1842,
  "output_tokens": 47,
  "quality_score": 1,
  "response_text": "B",
  "latency_ms": 1203,
  "source": "api"
}
```

`source` is `"api"` for token-counted runs and `"cli"` for behavioral runs. A single prompt produces up to 4 records: `api/before`, `api/after`, `cli/before`, `cli/after`.

## `/token-benchmark` Skill

### What It Does

1. Validates prerequisites: API keys present, CLI binaries on `PATH`
2. Optionally syncs `fixtures/manifest/` from live `~/.claude/` / `~/.gemini/` / `~/.antigravity/` when `--sync-fixtures` is passed
3. Runs `harness.py` — streams per-provider progress to stdout
4. Calls `reporter.py` to regenerate `TOKEN_BENCHMARK.md`
5. Prints a summary table
6. Prompts whether to commit the updated report

### Invocation Variants

```bash
/token-benchmark                     # full run, all providers
/token-benchmark --providers claude  # single provider (faster)
/token-benchmark --sync-fixtures     # update manifest snapshot first, then run
/token-benchmark --api-only          # skip CLI behavioral tests (no binaries needed)
/token-benchmark --report-only       # regenerate report from existing results, no new run
```

### Prerequisites

| Requirement | Source |
|-------------|--------|
| `ANTHROPIC_API_KEY` | [console.anthropic.com](https://console.anthropic.com) |
| `GEMINI_API_KEY` or OAuth token | Google AI Studio or `gcloud auth` |
| `claude` binary on PATH | Claude Code CLI install |
| `gemini` binary on PATH | Gemini CLI install |
| `antigravity` binary on PATH | Antigravity install |
| `anthropic` Python package | `pip install anthropic` |
| `google-generativeai` Python package | `pip install google-generativeai` |

## Out of Scope

- Cursor IDE token measurement (no CLI interface for subprocess testing)
- Codex CLI (not listed in the target providers)
- Per-skill or per-command token breakdown (aggregate per run only)
- Real-time streaming token counting (snapshot-per-call only)
- Cost estimation in dollars (token counts only; pricing changes over time)
