# apm_publish_allowlist.txt — documented-placeholder exemptions for
# apm_publish_gate.sh's in-script regex scan (T048/FR-030, Decision D).
#
# One POSIX extended regular expression (grep -E syntax) per line. Blank
# lines and lines starting with # are ignored: the gate strips both before
# ever handing this file to `grep -f`. Keep every comment line
# self-contained (no parenthesis or bracket left open across a line break) —
# some grep implementations reject a malformed pattern outright, and this
# file's raw form is not itself covered by the strip step.
#
# Each finding the scan's regex categories extract — machine-local-path,
# private-email, private-tracker-url, private-remember-ref,
# machine-hostname — is matched as an exact whole-string match, not a
# full-line search, against every pattern in this file. A match against ANY
# pattern here allowlists that one finding; any unlisted hit still blocks
# the publish. This file is the only sanctioned way to let a documented
# placeholder through the gate — nothing else does. The canonical example is
# literal "<name>" prose, such as "/Users/<name>" in a doc or template.
#
# Keep entries narrow. A pattern here silently exempts every future match,
# so prefer anchoring to the literal placeholder text over a broad wildcard.

# Literal doc/template placeholders using "<name>" rather than a real
# username — the scan's own examples above, and any comparable prose.
^/Users/<name>(/.*)?$
^/home/<name>(/.*)?$
^~<name>$
