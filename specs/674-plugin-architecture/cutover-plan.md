## Bottom line

The hard cutover is the right call for Claude Code and should proceed — but NOT as a packaging
change, because it is primarily a RENAME of all 108 slash commands. I measured this directly on
claude 2.1.220: `claude -p '/writing-rules'` returns `Unknown command: /writing-rules`, while
`/hookify:writing-rules` loads the skill. A plugin skill is reachable only as
`<plugin>:<skill>`. So the cutover's real cost is not moving files, it is that `/git-commit`
becomes `/manifest-forge:git-commit` everywhere: in the user's muscle memory, in
docs/COMMANDS.md, in `/help`, and in **33 cross-skill invocation sites across 18 SKILL.md bodies**
(re-measured 2026-07-30). That last set is the dangerous half, and it splits in two: 19 slash-form
calls a grep can find, plus **14 slashless dispatch-prose sites a slash-grep cannot** — see the
table in the next section. `issue-dev-auto` calls `/pr-address-comments`, `/project-verify` and
`/pr-review` by bare name inside an autonomous loop, so post-cutover each sub-agent's call silently
fails, the sub-agent improvises, and the loop reports success. `docs-all` does the same thing
without a slash and prints a fabricated per-skill success table. No error, no log line. Nothing in
any of the four designs mentions naming at all.
Second decisive fact: F8 is real and unfixable, though **narrower than first stated**. Re-verified
on this machine: `~/.cursor/skills`, `~/.gemini/skills`, `~/.codex/skills` and
`~/.antigravity/skills` are all symlinks to `~/.claude/skills`, and `~/.config/devin/skills` is
ABSENT (Devin inherits by reading `~/.claude` natively via `read_config_from.claude`, not through a
skills dir).

Plugins install to a Claude-Code-only, version-pathed

## The decision that gates everything

Measured on claude 2.1.220:

```
$ claude -p '/writing-rules'            -> Unknown command: /writing-rules
$ claude -p '/hookify:writing-rules'   -> loads the skill
```

A plugin skill is reachable **only** as `<plugin>:<skill>`. So the cutover renames every one of
the 108 slash commands: `/git-commit` becomes `/manifest-forge:git-commit`. There is no bare
alias to fall back on. **If that is not acceptable, the hard cutover is off** and the right shape
is additive plugin publishing with `~/.claude/skills` retained.

The dangerous half is not muscle memory — it is cross-skill invocation. **Re-measured 2026-07-30;
the earlier "15 skills / 33 bare `/name` calls" was right in magnitude and wrong in kind.** The 33
is real but it is a SUM OF TWO CLASSES, and only one of them carries a slash.

Counts below are the **tool's** output, not a hand sweep — `skill_reference_check.py` (T1.3,
landed) over `.apm/skills/**/*.md`, reproducible with
`python3 configs/claude/scripts/skill_reference_check.py --roots .apm/skills --json`:

| Class | Occurrences | Skills | Caught by a `/<name>` grep? |
|---|---|---|---|
| **A — slash-form** `` `/project-verify` `` | **22** (19 SKILL.md + 3 sidecar) | 10 | ✅ yes |
| **B — dispatch, ANY markup** ``run `docs-improve-readme` `` · `**upload-to-stitch**` | **15** | 11 | ❌ **structurally invisible** |
| **BLOCKING total (A+B)** | **37** | **20** | — |
| C — prose pointers | 90 | 28 | ❌ (cosmetic: breaks the reader, not the runtime) |
| D — relative file link `../extract-static-html/SKILL.md` | 4 | 1 | ❌ (survives as partitioned — T3.6 pins it) |

> `generate-design:164` reads *"Delegate to the **upload-to-stitch** skill"* — a dispatch in
> **bold**, not backticks. Any detector keyed on code spans misses it, and both of my earlier
> sweeps were. The blocking surface is **37 across 20 skills**. Class C rose 79 → 90 for two
> reasons, both of them prior undercounts: the tool scans sidecars (`references/`, `prompts/`) that
> the hand sweep never opened, and the hand sweep had a false negative on

> The lesson generalises to T1.1: **do not remediate from a hand list.** Drive it from
> `--json` output, or the sites nobody's regex anticipated stay behind.

Class A is the loop case and it is confirmed: `issue-dev-auto:81` reads ``run one cycle:
`/pr-address-comments`, then `/project-verify`, then `/pr-review` `` and `:52` reads ``Run
`/project-verify` ``. Post-cutover each is an `Unknown command`, the sub-agent improvises, and the
loop reports success. No error, no log line.

Class B is the one that breaks the *fix*. `docs-all` dispatches `docs-improve-readme`,
`docs-generate-diagrams` and `docs-improve` as sub-agents **by bare name with no slash**, then
prints a per-skill success table (`README 464 → 186 lines`). `code-to-design` delegates to three
Stitch skills the same way. A sub-agent handed a bare name post-cutover cannot resolve it — plugin
skills are addressable only as `plugin:skill` — so it freehands and reports success. **T1.3's gate
as originally written greps for `/<name>` and would therefore have shipped green over all 14 Class-B
sites**, i.e. over `docs-all`, the exact skill whose failure mode is a fabricated success table.
The gate must match on catalog names in dispatch context, not on the slash.

Class C (79 pointers such as "see also `pr-review`") is prose; it does not break at runtime and is
explicitly out of scope for the blocking gate. It still needs a docs pass so the names a user is
told to type are typeable.

Class D is the one piece of good news: 4 relative links, all in `code-to-design`, all pointing at
Stitch skills that land in the SAME bundle (`stitch-design`), so they keep resolving as siblings
under `plugins/stitch-design/skills/`. No work — but T3.6 pins it as a partition invariant, because
nothing today would stop a future rebalance from moving one of the five and silently breaking all
four. (These four are also what measured-facts.md M8's "strict: 1 skill, 4 references" was actually
counting — file paths, not slash commands. Corrected there.)
