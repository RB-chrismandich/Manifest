# Implementation Plan: Graphify Integration

**Branch**: `364-graphify-integration` | **Date**: 2026-06-28 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/364-graphify-integration/spec.md`

## Summary

Make graphify (an AI-powered knowledge-graph generator + `/graphify` skill, PyPI package `graphifyy`) a first-class **default-enabled** managed tool inside Manifest's bootstrap pipeline. The integration adds: (1) a `--enable-graphify`/`--disable-graphify` service toggle persisted to `services.yml`; (2) idempotent CLI installation (`check_uv` + `install_graphify` via `uv tool install graphifyy`); (3) a vendored thin `/graphify` skill in `.retired skill supply/skills/` that deploys across all enabled assistants through the existing pipeline; (4) health-check reporting; and (5) documentation + tests. Graphify is treated as a managed *tool/skill*, **not** a consensus agent — it is deliberately excluded from `parallel_agent.py` agent gating.

## Technical Context

**Language/Version**: Bash (bootstrap, scripts — `shellcheck` clean), Python 3.10+ (graphify CLI dependency; `agents/config.py` runtime), Markdown/YAML (skills, config, docs). No new app language introduced.

**Primary Dependencies**: New external — `uv` (Astral Python tool installer, not currently used in repo) and `graphifyy` (PyPI; Python ≥3.10). Existing internal (edited) — `bootstrap/lib/{config,install,deploy}.sh`, `.retired skill supply/skills/` pipeline, `configs/claude/scripts/check_status.sh`. Read-only / transitive (NO source edit) — `agents/config.py`: `is_enabled()` (config.py:223) defaults unknown services to `True` and parses `services.yml` dynamically, so graphify needs no registration there and is **deliberately kept out** of the agent-defaults dict (lines 209–215) so it is never counted as a consensus agent (D4).

**Storage**: Config state in `~/.claude/config/services.yml` (generated by the `write_services_config()` heredoc). Graphify's own outputs (`graphify-out/`) are user-workspace artifacts, out of scope for Manifest to manage.

**Testing**: `bats tests/bats/` (bootstrap_services.bats, check_status.bats), `pytest tests/python/` (agents/test_config.py), `shellcheck`, `yamllint`. Test-first where practical per Constitution Development Workflow.

**Target Platform**: macOS (Intel + Apple Silicon) and Linux (apt/dnf/yum/pacman) — same matrix bootstrap already supports. No new platform.

**Project Type**: Configuration-management / deployment system (single repo, shell + Python + skill artifacts). Not a web/mobile app — no `src/` tree.

**Performance Goals**: Bootstrap overhead for graphify install on a clean machine is dominated by `uv`/`graphifyy` download; idempotent re-runs are sub-second no-ops (existence-guarded). No hot-path concerns.

**Constraints**: Idempotent + existence-guarded installs (Principle V); never abort the whole bootstrap on graphify failure (FR-006/SC-005); no credentials required by default (host-agent backend, FR-011); source of truth is the heredoc, not the committed `services.yml` copy.

**Scale/Scope**: ~12–15 files touched across bootstrap libs, one new skill, check_status.sh, 7 docs, 3 test files. Net change exceeds 200 lines → triggers Constitution Principle II (parallel-agent cross-verification before merge).
