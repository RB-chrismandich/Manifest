# Migration Inventory — Feature 522

**Produced by**: T012 (FR-020, FR-034, R3) · **Counts measured**: 2026-07-27

Every artifact Manifest deploys, classified, with an explicit disposition. T012
requires the scripts and config YAMLs be **decided, not deferred** — and where
this document defers, it says so and says why, because "a deferral leaves the
drift fix partial by definition and must be stated as such."

The spec's "54 top-level (88 recursive) scripts" is stale — the tree has grown
to 65/170. Recorded rather than silently corrected, because the ratio is the
part that matters: **two thirds of the script tree is below the top level**, so
any migration that reasons only about top-level entries covers a third of it.

## Classification and disposition

### 1. Markdown primitives — **MIGRATE** (this is the MVP domain)

Skills (108), agents (10). These are exactly what APM was built to carry: inert
files with a defined target directory per harness. Cell (a)/(b) measured all
three primitive types deploying at user scope.

Disposition: **APM-owned.** `skills` is the first and only registered domain;
`agents` follows once `skills` is proven on real content (T019).

### 2. Config YAML — **MIGRATE, BUT NOT FIRST** (22 files)

Deployable as inert files, with one complication that had to be resolved before
they could move: `command_config.yml` was mutated *in the deployed copy* by
`install_issue_hooks.sh`, making it a build output holding user state.

Disposition: **APM-owned, after T051.** That blocker is now cleared — the opt-in
moved to `~/.manifest/issue_hooks.yml`, a file no package owns, so the config
YAMLs are ordinary build outputs again. `preserve_issue_sync_gates()` survives
only as a migration shim.

Two config files are **excluded** and must stay excluded:

- `apm_domains.yml` — the ownership registry itself. If APM deployed it, the
  answer to "who owns this domain?" would arrive by the very pipeline whose
  ownership is in question.
- `services.yml` — generated by `write_services_config()` from bootstrap toggles
  at run time, not copied from source. It is not a deployable artifact; it is
  output. (See the dual-generator note in the repo's own history: the committed
  copy is a drift-test fixture, not the source.)

### 3. Scripts — **DEFERRED, EXPLICITLY** (65 top level / 170 recursive)

**This is the honest gap in the migration, stated as T012 requires.**

Scripts are not inert. They are executable, they resolve siblings by relative
path (`${SCRIPT_DIR}/../config/...`), several source shared libraries
(`apm_domains_lib.sh`, `apm_hash_lib.sh`), and some are installed outside the
harness homes entirely (`~/.local/bin/sync-skills`, `~/.local/bin/apm-dev-sync`,
`~/.local/bin/manifest`). APM's model — a package declaring primitives with a
target directory per harness — has no notion of an executable that must land on
`PATH` with its siblings intact.

Disposition: **stay on the legacy pipeline for this feature.** Consequences,
stated rather than glossed:

- The drift fix is **partial**. Scripts remain deployed by `rsync` with no
  ownership manifest, so the orphan class this feature exists to eliminate
  still exists for them.
- `deploy_reconcile.sh` therefore cannot be retired, contrary to the spec's
  scope table, which lists it as superseded by drift detection. It is superseded
  *for migrated domains only*.
- Any future attempt to migrate scripts must first answer the `PATH`-install and
  relative-sibling questions. Neither is measured.

### 4. Generated — **OUT OF SCOPE, BY DESIGN** (110 Cursor rules + docs)

`generate_cursor_rules.sh`, `generate_cursor_agents.py`, `generate_cursor_mcp.py`
compile source primitives per harness; `generate_commands_doc.py` renders
repository documentation.

Disposition: the per-harness compilers are **replaceable** by an APM-targeted
build once skills migrate (US2). `generate_commands_doc.py` **stays on the
legacy pipeline permanently** — it produces repository documentation, not
per-harness deploy config, and no APM target generates catalog indexes. US2's
"no hand-run generator" claim explicitly does not cover it.

## What this means for the feature's claim

FR-014 asks for exactly one writer per deployed area. After this migration that
holds for **skills, agents, and config YAML**. It does **not** hold for the 170
script files, which remain rsync-deployed and unmanifested.

The feature is therefore a drift fix for the primitive and config surface, not
for the whole deploy. Anyone reading SC-001..SC-004 as "drift is eliminated"
should read this section first.
