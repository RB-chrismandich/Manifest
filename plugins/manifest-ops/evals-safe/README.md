# Safe Ops eval suite

This authored suite substitutes for the 15 Ops cases that depend on the existing scaffold scripts. Case IDs are preserved so reports can be reconciled directly; the source cases remain unchanged. Safe graders and non-`cis-*` prompts were written separately; the five `cis-*` prompts retain the original generic request so platform selection depends on repository metadata. Every `scaffold.sh` below writes fixed-path fixture files and initializes a Git repository in the fresh runner's current workspace. Each case has only a synthetic workspace-local `origin` URL matching its original case for platform detection, not a live network remote. None of the original scaffold scripts were run.

## Differences and parity

- Safe case IDs and the acceptance intent are retained. Grading prose and non-`cis-*` prompts are independently authored; all five `cis-*` prompts use the original generic wording: “The repo is checked out in the current directory.” followed by “Set up CI/CD for this repo.”
- All 15 scaffolds use `git init --quiet --template= .` and `git remote add origin <original-url>` to preserve the original Git prerequisite and platform-autodetection metadata. These commands create only workspace-local Git metadata, copy no Git templates, and do not contact the configured URL. The synthetic origin is for detection only; no repository history or live network remote is needed. The Go module path, GitLab CI files, and GitHub workflow fixtures remain where relevant.
- `cis-02-pnpm-next` supplies an inert, minimal pnpm 9 `pnpm-lock.yaml` here-doc with importer dependency names and versions matching `package.json`, so `ci-setup` detects pnpm. It is a detection fixture, not a fully resolved installation lockfile. The original content grader does not require or penalize frozen-lockfile flags. No package manager or network is used to synthesize it.
- No consumer-facing acceptance criterion was omitted for safety. Network/install commands that appear inside fixture files (for example, the GitLab shared-config `curl` line in `cdd-03`) are inert text written as input; the safe scaffold never executes them.

## Safety bounds

Each `scaffold.sh` uses `/bin/sh`, `set -eu`, `umask 077`, fixed relative paths, `mkdir -p` where needed, and here-doc writes. All 15 scripts additionally run only workspace-local `git init --quiet --template= .` and `git remote add origin <original-url>`; the latter records a synthetic URL for detection in local Git configuration without contacting any remote. No Git templates are copied. The scripts do not change directory, write outside the workspace (including absolute or home paths), contact a network, fetch, install packages, delete files, create symlinks, commit, push, or run any CI command. They assume the evaluator supplies a fresh workspace and create fixture files and Git metadata only beneath it. No live network remote is used. The original `evals/*/scaffold.sh` scripts were not executed or modified.

## Run this suite

From `plugins/manifest-ops/`:

```sh
claude plugin eval . --eval-dir evals-safe --ablation with-without \
  --judge-model opus --trust-plugin --no-publish -j 2 --scaffold \
  --allow-tools Write Edit Bash
```

The CLI writes results under `evals-safe/results/`. `--scaffold` is valid here
because this alternate suite and its scripts were authored for this repository;
do not pass it for the pre-existing `evals/` cases.
